# 개발·검증 안내

이 문서는 구현을 읽고 로컬에서 확인하는 순서를 설명합니다. 기능 목록, 테스트 정의, 실제 실행 결과를 구분하며, 확인하지 않은 실행을 성공으로 기록하지 않습니다.

## 1. 화면에서 저장까지

### 집필 화면

`src/app`의 페이지와 `src/components`에서 프로젝트·권·챕터, 페르소나와 집필 도구를 구성합니다. 화면 기능을 읽은 뒤 해당 `src/app/api` 경로의 입력, 응답, 저장 처리를 함께 확인하세요.

### 챕터 생성

`src/app/api/projects/[id]/generate/route.ts`는 프로젝트·페르소나를 조회하고 `prompt-builder.ts`가 만든 문맥을 공급자에 전달합니다. 생성한 챕터와 사용량을 저장하고, 이후 보조 요약을 시도합니다.

`src/lib/ai/providers`는 Gemini·OpenAI·Anthropic을 공통 생성 인터페이스로 연결합니다. 인터페이스가 같다는 것이 모든 모델·옵션·보조 기능이 같다는 뜻은 아닙니다. 일부 요약과 삽화 프롬프트 작성은 Gemini 경로에 남아 있습니다.

### 스트리밍

`src/app/api/projects/[id]/stream/route.ts`는 `start`, `chunk`, `done`, `error` 이벤트를 SSE로 보냅니다.

- Gemini: 모델 스트림에서 받은 내용을 전달한 뒤 최종 JSON을 해석하고 저장합니다.
- 다른 공급자: 전체 생성과 저장 후 내용을 나눠 전송합니다. 모델 토큰이 생성되는 즉시 전달하는 경로가 아닙니다.

JSON 해석·저장 실패와 생성 실패는 따로 확인해야 합니다. 현재 오류 안내가 어느 실패까지 구분하는지는 실제 경로를 기준으로 판단하세요. 화면을 닫는 동작만으로 외부 모델 실행·과금이 취소된다고 보장하지 않습니다.

### 문맥과 저장

`src/lib/memory/memory-manager.ts`는 설정집, 권별 시놉시스, 챕터 요약, 직전 챕터, 선택한 지식 파일을 조합합니다. 문맥을 줄이는 대신 세부 내용이 빠질 수 있고, 토큰 수는 제공자 토크나이저가 아닌 추정치입니다. 모델별 입력 한도 준수나 장편 전체 일관성을 보장하는 방식으로 소개하지 않습니다.

`src/lib/db/index.ts`는 `data/novelforge.db`를 열고 `schema.sql`을 적용합니다. DB가 로컬에 있다는 것과 AI 요청이 로컬에서만 처리된다는 것은 다릅니다. 생성·요약·삽화 기능에 필요한 내용은 외부 AI 제공자에 전송됩니다.

## 2. 테스트 실행

저장소 루트에서 의존성을 설치한 뒤 실행합니다.

```bash
npm ci
npm run test:ci
npm run typecheck
npm run lint
npm run build
```

각 명령의 종료 상태를 따로 확인하세요. 한 명령이 성공했다고 나머지 검사나 실제 AI 연동이 성공한 것은 아닙니다.

| 명령 | 의미 |
|---|---|
| `npm test` | 기존 Jest 설정에 맞는 단위 테스트 실행 |
| `npm run test:watch` | 전체 테스트의 변경 감시 모드 |
| `npm run test:ci` | 단일 프로세스의 비대화형 Jest 실행. GitHub Actions를 자동 구성하는 명령은 아님 |
| `npm run typecheck` | TypeScript 정적 검사 |
| `npm run lint` | 현재 ESLint 설정 기준 검사 |
| `npm run build` | Next.js 빌드. API 실호출·브라우저 동작 검사와는 별개 |

현재 의존성과 `jest.config.js`를 그대로 사용합니다. 명령을 추가한 것이 기존 검사 실패를 해결했다는 뜻은 아닙니다. 실패할 경우 Node·npm 버전, 실행 명령, 오류를 남기고 원인을 확인하세요. 테스트를 건너뛰거나 assertion을 약하게 바꿔 성공으로 표시하지 않습니다.

### 기존 테스트의 범위

| 파일 | 검사 대상 | 포함하지 않는 검증 |
|---|---|---|
| `src/__tests__/genre-presets.test.ts` | 장르 프리셋 필드와 조회 | 생성 문장의 품질 |
| `src/__tests__/novel-settings.test.ts` | 설정을 프롬프트 규칙으로 변환 | 모델의 실제 규칙 준수 |
| `src/__tests__/memory-manager.test.ts` | 모의 DB 기반 문맥 구성 | 실제 DB·장편 전체 일관성·모델 입력 한도 |
| `src/__tests__/exporter.test.ts` | 모의 DB 기반 TXT·HTML 출력 | EPUB 리더 호환성·전체 XSS 안전성 |

기존 테스트는 실제 모델 호출 없이 로컬 로직을 대상으로 작성돼 있습니다. 설치·빌드 중 네트워크 접근까지 없다는 보장은 아닙니다. 실제 모델 응답, 브라우저 상호작용, EPUB 출력 검증은 별도로 수행해야 합니다.

특히 특수문자가 없는 입력에서 `<script>`가 없음을 확인하는 것만으로 HTML 이스케이프가 안전하다고 판단하지 않습니다. 현재 검사하는 범위와 이후 보완할 경계 사례를 구분하세요.

## 3. 안전한 수동 확인

화면을 확인할 때는 직접 만든 시험 원고와 로컬 데이터만 사용합니다.

1. `.env.local`을 덮어쓰지 않고 필요한 키를 로컬에서 설정합니다.
2. `npm run dev -- --hostname 127.0.0.1`로 실행하고 프로젝트·페르소나·챕터 화면을 확인합니다.
3. 유료 AI 기능을 실행하기 전 입력과 계정의 사용 한도를 확인합니다. 공급자 선택만으로 보조 기능의 Gemini 의존성이 사라지지는 않습니다.
4. 생성 결과 표시와 DB 저장, 새로고침 후 조회를 구분해 확인합니다. 실패는 실패로 기록합니다.
5. TXT·HTML을 확인하고 EPUB은 실제 리더에서 따로 확인합니다. 캡처에는 키·개인 경로·실제 원고를 남기지 않습니다.

이 절차는 검증 계획이며 실행 결과가 아닙니다. 루프백 바인딩은 노출을 줄이는 실행 옵션이지, 인증·권한·요청 검증을 대체하는 보안 경계가 아닙니다.

## 4. 기능을 확장하기 전에 확인할 것

- 모델 ID와 이미지 요청 매개변수는 코드에 고정된 부분이 있습니다. 현재 계정과 API에서 사용할 수 있는지 확인하고, 비용 표도 별도로 갱신해야 합니다.
- 공급자별 생성, Gemini 보조 요약, 이미지 생성은 별도 경로입니다. 한 경로의 성공을 전체 기능의 성공으로 묶지 않습니다.
- 토큰·비용 추정은 청구액이나 강제 비용 제한이 아닙니다. 스트리밍과 일반 생성의 사용량 기록 범위도 비교해야 합니다.
- 공개 서비스로 전환하려면 사용자 인증·데이터 접근 권한·입력 검증·요청 제한·비용 통제·로그 정제를 별도로 설계하고 검증해야 합니다.

기존 테스트를 실행하지 않은 상태에서 통과 수·커버리지·성능 수치를 문서에 추가하지 않습니다. 변경은 소규모 PR로 나누고, 실행한 검사와 실행하지 못한 검사를 PR에 함께 기록하세요.
